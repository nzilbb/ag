This annotator tags words with their lexical entries (pronunciations, frequency, etc.) according to the CELEX English lexicon .

The CELEX tagger basically takes word annotations already stored on one layer, uses each one to look up certain data in the CELEX database, and stores the results of the lookup on another layer.

The main settings for a CELEX layer are:

  • Token Layer - This is where the layer manager will get the words it needs to look up from. Under most circumstances, this should be the orthography layer, which contains the orthographic (ordinary spelling) representation of the word.
  • CELEX SQL Query - This defines what should be looked up, given a word taken from the Token Layer. This takes the form of an SQL SELECT statement, which is used to query the CELEX database. However, you don't need to know anything about SQL to configure the layer, you can use pre-prepared queries that are frequently desired, simply by clicking the option you want to the left of the SQL query:
    • Phonology - the standard pronunciation of the given word, expressed using the DISC encoding for phonemes, with syllabification and stress-marking removed
    • Syllable Count - the number of syllables in the word
    • Morphology - the morphological parse for the word
    • Syntax - possible syntactic categories for the word
    • Frequency (wordform) - the frequency of the wordform in the Cobuild corpus
    • Frequency (lemma) - the frequency of the word's lemma in the Cobuild corpus
    • Syllables from Phonology - if the segments layer has been populated with phone annotation (e.g. from HTK forced-alignment), then the syllable structure and stress pattern of the words can be recovered using this option. For this to work:
      1. The layer must be a word layer
      2. The layer must be a time-intervals layer
      3. The source layer must be the segments layer (this layer is automatically selected when you click on this option)
      4. The source layer must contain phones that correspond to a phonemic transcription in CELEX
      5. The Delimiters must be set to - (see below)
  • First variant only - Any of the queries above may return more than one result for a given orthographic word - e.g. the word mean can be a verb, adjective, or noun. All of these possibilities would be annotated against an instance of the word mean on a "syntax" layer, unless you tick the First variant only option, in which case only the most frequent possibility will annotate the word.

Other options are for special cases, and include:

  • Target Language Pattern - Specifies what language to target for annotations. This is a regular expression that is matched against the language code (two-letter ISO-639-1 codes like en, possibly with a suffix to indicate a variety, like en-nz) of each word in order to decide whether to annotate it or not. If this setting is left blank, all words are annotated, regardless of language (this can help boost performance on very large databases). The language of a word is determines as follows:
    1. If the word is inside an annotation on the layer specified by the Phrase Language Layer setting, then this annotation determines the word's language. If not:
    2. The transcript attribute specified by the Transcript Language Attribute setting is assumed to be the language of the word. If the transcript has no language label:
    3. The language of the corpus of the transcript is assumed to be the language of the word.
  • Delimiters - This is a list of characters that are used to split the resulting annotation into chunks, and is used when the Source Layer is the segments layer. Each chunk is used to identify a group of segments that belong together, and so the result is a set of annotations that partition the word by the resulting chunks. This can be used to look up the syllable-marked version of the phonemic transcription, given the segments chosen for the word, and then produce syllable annotations for the word by using hyphen - as the delimiter.

First Variant Only

In many cases, a given wordform will have multiple possible matches in CELEX. For example, on a Syntax, layer, the word fine might be an adjective, an adverb, a noun, or a verb. All of these possibilities will be added as annotations on all tokens of the word fine.

If you want to ensure that each token has only one annotation, tick the First match only option. This will annotate words only with the first matching annotation from CELEX. If you use the predefined definition options, these order the annotations most-frequent-first, so the most frequent annotation (e.g. adjective, in the case of fine) will be chosen as the one annotation.

NB if you are computing syllable counts in order to then compute speech rate, then you must tick this option. Otherwise, words with multiple possible syllable counts will have all possibilities added together. e.g. the word family can have either 3 or 2 syllables; if you do not tick First match only, then this will count as a 5-syllable word for speech rate computation.

Testing

Below the settings a box labelled Test word with the word testing in it.

This allows you to test your settings for the layer and see what the resulting annotations would be for a single word. The word is testing by default, but if you type another word in that box, that word will be used with your definition, and the result or results will be displayed below the word.

For example, if you want to see what annotations your 'Syntax' configuration will generate for the word fine, type fine in the box to replace testing, and you will see various syntactic-category labels appear listed in the box below it (A, ADV, N, and V) - these are the possible syntactic categories for fine according to CELEX, and so each token of the word fine will be annotated with all of these labels.

Manually Specify SQL

If you are familiar with how to write SQL SELECT queries, you can write your own query. The CELEX database schema is shown at the bottom of this page.

As can be seen from the example queries by selecting the preprepared query options, a single question mark ? is used as a parameter to identify the orthography of the word being looked up (or more correctly, the annotation on the Source Layer that's being looked up).

Full information about the tables and fields available are in the database schema document.
